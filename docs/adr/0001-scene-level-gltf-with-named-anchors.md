# 场景级 glTF 取代程序化大陆,板块以同名锚点定位

Status: accepted (2026-09-08, 重构拷问定稿)

`World.vue`(1481 行)用纯 three.js 程序化生成 AETHERION 大陆(value-noise 地形、图元拼装地标、代码摆 marker),全仓库无任何外部 3D 资产。决定:把大陆改为**由建模者产出的 glTF 场景**,前端只负责加载、拾取与展示——渲染场景切分为两个文件:`top`(天空+地表,连续世界共 scene)与 `under`(地下,独立 scene);板块不再存 x/z 坐标,改由模型内**与板块 id 同名的锚点**定位,前端按名字寻址。

**理由**:程序化代码把所有几何决策写死在 JS 里,美术无法直接改进世界;数据坐标 + 代码求高这套机制在模型时代不存在(高度在 Blender 里定)。锚点契约让"模型改、锚点跟着改"天然一致,`world.json` 退回纯内容,同时消掉 `markerByRegion` 这类代码与数据耦合。

**拾取与展示实体**:板块的可点击实体是建模者搭在场景里的地标本体(landmark,与板块同名),不是前端生成的通用宝石;hover 反馈(缩放/高亮)与发光呼吸由前端驱动锚点下材质(glTF emissive 通道可行),场景加载后统一遍历命名锚点挂载动画。

**光照**:保留前端实时灯光(hemi + dir),网站亮色主题 = 3D 白天、暗色 = 3D 黑夜的昼夜联动由前端驱动 `sceneTop` 光照 lerp,地下恒定;模型只带几何与 PBR 材质、不烘焙。若后续材质在昼夜双光下效果不佳,可去掉昼夜联动(单一时段光照),该改动被隔离在灯光模块内。

**性能兜底**:模型若导致网页卡顿,优先前端手段(遮罩/降级渲染)缓解,不先更换材质或砍资产。

## Considered Options

- **保留程序化地形,仅元素换 glTF**:地形仍是代码生成,美术改不了大陆形状,不符合"模型持续更新"的目标。拒绝。
- **坐标仍存 JSON,前端摆 marker**:Y 值需要手动填或对模型 raycast,坐标与模型一旦不一致就悬空。拒绝——锚点把位置职责交给建模侧。
- **前端继续生成 marker 视觉**:12 个板块点击物雷同,与"地标即展示"的域模型不符。拒绝——marker 由模型自带,前端只驱动反馈。
- **整体单个 GLB**:三层混一文件,任一层改动需重导重传全部,jsDelivr 20MB 预算最紧。拒绝——按渲染场景切 `top`/`under` 与现有双 scene 架构同构。
- **灯光烘焙进贴图**:昼夜=两套烘焙或放弃昼夜,模型迭代成本高。拒绝——前端实时灯保留可迭代性。

## Consequences

- `world.json` 升级为对象:`models`(top/under URL)+ `regions`(删 x/z,保留 color 供 UI 强调色);`src/content` 与 admin 同步改。
- `World.vue` 中程序化生成代码(地形/树/桥/晶簇/王门等 build*)删除或归档,引擎骨架(场景、相机、flyTo、切层、拾取框架、昼夜灯)抽入 `src/three/` 模块导出。
- 锚点命名是前端与建模侧的契约:id 即节点名;缺失锚点只影响对应板块(无点击目标、不报错),不影响其他板块与整个场景。实现注记:World 加载后 traverse 场景,把名字匹配板块 id 的节点登记为 landmark,该节点的 mesh 进入拾取列表(2026-09-08 M3 落地)。
- 渲染场景 `top`(天空+地表)与 `under`(地下)保持现有 sceneTop/sceneUnder 拓扑,切层动画/相机中继逻辑不动。
- 资产命名 `aetherion-top.glb` / `aetherion-under.glb`,见 ADR-0002 托管管线。
